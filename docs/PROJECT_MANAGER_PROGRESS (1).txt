4. PROJECT CREATION WORKFLOW
-----------------------------

The workflow now works in these stages:

Step 1:
    The manager clicks "New project".

Step 2:
    The manager enters:
    - Project name
    - Project description/client
    - One or more project members

Step 3:
    The "Configure project" button is disabled until all required project
    details are complete:
    - Project name is filled
    - Description is filled
    - At least one member is selected

Step 4:
    After clicking "Configure project", the project is created as a private
    draft and the manager is taken to that project's configuration section.

Step 5:
    The manager configures the required document count for each phase.

Step 6:
    The manager clicks "Create project".

Step 7:
    The project is posted and becomes visible in the Projects page.

Step 8:
    The manager workspace resets to the initial project creation state so
    another project can be created immediately.


5. DRAFT AND POSTED PROJECT VISIBILITY
---------------------------------------

- Newly created projects are private drafts.
- Draft projects are visible to the Project Manager for setup.
- Draft projects are not shown to normal users.
- Normal users only see projects after the manager clicks "Create project".
- Posted projects become available through the Projects page.
- Project status is displayed as either:
    - Draft
    - Posted
    - Published


6. PROJECT CONFIGURATION
------------------------

The configuration section includes:

- Project status summary
- Total required documents
- Number of project members
- Phase-by-phase document planning
- Numbered phase indicators
- Required document count input for every phase
- Validation before posting

Posting is blocked unless every phase has a required document count greater
than zero.

The Mandatory documents field was removed as requested.

Required document values are saved through the backend phase update API.


7. PROJECT DETAILS RESET AND EDITING
-------------------------------------

The configuration section contains a "Reset details" button.

When selected:

- The configuration section is hidden.
- The previous project details form is reopened.
- The existing project name is restored.
- The existing description is restored.
- Previously selected members are restored.
- The manager can add members.
- The manager can remove members.
- The manager can select different members.
- The manager can change the project name or description.

While editing:

- The edit state is visibly highlighted.
- The form explains that saving will return to project configuration.
- The manager can click "Save changes".

After saving:

- Project name and description are updated.
- Project members are updated.
- The same project remains selected.
- The manager returns to that project's configuration section.


8. PROJECT POSTING
-------------------

The project posting button is now labelled "Create project" so the workflow
is easier to understand.

When clicked:

- The project is marked as published.
- The project becomes visible in the Projects page.
- A success message is displayed.
- The setup state is cleared.
- The workspace returns to the new-project creation state.

The button also includes a loading state to prevent duplicate submissions.

18. CURRENT USER WORKFLOW SUMMARY
----------------------------------

For the Project Manager:

1. Log in using the Project Manager account.
2. Open Manager workspace.
3. Click New project.
4. Fill in project name and description.
5. Select project members.
6. Click Configure project.
7. Set required document counts for every phase.
8. Use Reset details if project information or members need changing.
9. Save changes to return to configuration.
10. Click Create project.
11. The project becomes visible in Projects.
12. The workspace resets for another project.

For normal users:

1. Log in using their registered email and password.
2. Access the normal user application.
3. See projects after they are posted.
4. Access the relevant project phases and documents according to the
   application's access rules.
5. View project reports submitted by the Project Manager.
